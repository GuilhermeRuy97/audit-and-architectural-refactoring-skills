# Requirements

For each project, identify and document at least 5 problems, including at least:
- 1 (or more) problem of severity CRITICAL or HIGH
- 2 (or more) problems of severity MEDIUM
- 2 (or more) problems of severity LOW

- The problems should be identified using the classification scales defined in the README.md file.
- Focus on the problems with higher architectural or security impact.
- Document the findings in the "Manual Analysis" section of the `./README.md` file.

# Input > Output

- The inputs are the projects with problems available on `./projects-original/` directory.
- The outputs are the findings of the manual analysis in the "Manual Analysis" section of the `./README.md` file and the refactored code on `./projects-refactored/` directory.
- DO NOT change the code and files from the original projects on `./projects-original/` directory. The changes must be done on the `./projects-refactored/` directory.
